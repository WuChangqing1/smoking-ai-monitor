# 监控视频目录 / Monitor video directory

本目录存放平台的监控画面素材。**视频不入库**（见文末「关于 Git」），
部署时单独上传。

## 文件清单

| 文件 | 用途 | 播放速率 | 说明 |
|---|---|---|---|
| `main-monitor.mp4` | **主监控画面**（Camera 01） | 0.5× | 参与全站数据同步，并叠加异常检测框 |
| `camera-02.mp4` | Camera 02 循环画面 | 0.5× | 仅画面循环展示，不参与数据同步 |
| `camera-03.mp4` | Camera 03 循环画面 | 0.5× | 同上 |
| `camera-04.mp4` | Camera 04 循环画面 | 0.5× | 同上 |

主监控画面与其余机位的区别只有一个：**是否参与全站数据同步**。
主监控画面是页面数值的唯一时间来源（见 `src/video/VideoSyncContext.tsx`），
其余机位只是把现场素材循环播出来。

## 接入 / 替换步骤

**主监控画面**（`main-monitor.mp4`）

1. 把视频命名为 `main-monitor.mp4`，复制到本目录；
2. 把 `src/components/MonitorVideo.tsx` 里的 `MONITOR_VIDEO_VERSION` **+1**；
3. 重新 `npm run build` 并上传产物。

**其余机位**（`camera-02/03/04.mp4`）

1. 把视频按机位命名为 `camera-0X.mp4`，复制到本目录；
2. 把 `MonitorVideo.tsx` 里 `CAMERA_VIDEO_VERSION` 对应机位的版本号 **+1**；
3. 重新构建并上传。

> **为什么必须改版本号**：视频文件名固定，而 HTTP 缓存无法感知内容变化。
> 若沿用同一个 URL，浏览器会在缓存有效期内继续播放旧文件
> （曾因此出现「服务器已是新视频、页面上仍是旧视频」的问题）。
> 把版本号拼进查询串即可让 URL 变化，浏览器必然重新拉取。

## 视频不存在时会怎样

`MonitorVideo` 会先对视频路径发 HEAD 请求确认返回的确实是视频类型
（避免某些服务器对不存在的路径返回 `index.html` 且状态码 200 导致误判），
失败则回退到静态监控画面 `images/main-monitor-fallback.png`，
再由 `<video>` 的 `onError` 兜底。

因此**某个机位视频缺失不会报错、不会白屏**，只是该机位显示静态画面。

## 视频编码建议

- 容器：MP4（H.264 + yuv420p），浏览器兼容性最好；
- 分辨率：1280×720 或 1920×1080；
- 时长：7~60 秒循环片段（播放器已设置 `loop`）；
- 无音轨或有音轨均可（页面 `muted` 播放以满足浏览器自动播放策略）；
- 码率建议 ≤ 4 Mbps，文件尽量控制在 50 MB 以内。

## 关于 Git

`.gitignore` 已用 `*.mp4` 通配规则忽略视频（含仓库根目录下的素材）。
大视频请**部署时单独上传**（见 `deployment/README.md`），
不要直接提交 —— 这不会改变上面的固定接入约定。
